## Fix 1 — final test code (key new assertion)

The replacement `timeout_does_not_debit_quota` test pins the M3
invariant directly via `budget.snapshot().calls_used` on a SINGLE
slow cap:

```rust
/// Test C: SINGLE slow cap (200ms sleep, 100ms budget, 3-call
/// quota). Two consecutive `invoke_op` calls both return Timeout.
/// The key invariant is `budget.snapshot().calls_used == 0` across
/// both timeouts — the budget blew, but the quota bucket was
/// not touched. The 3-call quota is chosen so a hypothetical
/// regression that debits the quota before the handler runs would
/// surface as `calls_used >= 1` after the first timeout; with
/// the production handler-first ordering, the quota stays at 0
/// for both calls.
#[test]
fn timeout_does_not_debit_quota() {
    let (space, factory) = build_world();

    let plugin = PluginId { name: "sleep".into(), version: "0.1.0".into() };
    let decl = CapabilityDecl {
        name: "slow_timeout".into(),
        in_type: "any".into(), out_type: "any".into(),
        streaming: false, ..Default::default()
    };

    // 200ms sleep, 100ms budget, 3-call quota. The budget
    // blows on every call; the quota is only touched by
    // successful handler returns.
    let budget = CapabilityBudget::with_spec(
        100,
        QuotaSpec::unlimited().with_calls_per_minute(3),
    );
    let slot = factory.mint::<SleepResource>(
        CapKind::Sync, &decl, &plugin, budget,
        Arc::new(SleepResource { sleep: Duration::from_millis(200) }),
    );
    let typed: Arc<Capability<SleepResource>> = space
        .lookup_typed::<SleepResource>(slot)
        .expect("typed slow cap");

    // Pre-condition: fresh cap, calls_used = 0.
    let snap_before = typed.budget().snapshot();
    assert_eq!(snap_before.calls_used, 0, ...);

    // First call: Timeout.
    let r1 = typed.invoke_op(OperationRights::READ, serde_json::json!({}));
    assert!(matches!(r1, Err(CapabilityError::Timeout { .. })), ...);

    // After first Timeout: calls_used must still be 0.
    let snap1 = typed.budget().snapshot();
    assert_eq!(snap1.calls_used, 0,
        "M3 INVARIANT VIOLATED: first Timeout must NOT debit the quota; calls_used = {}",
        snap1.calls_used);

    // Second call: same slow cap, same quota bucket.
    let r2 = typed.invoke_op(OperationRights::READ, serde_json::json!({}));
    assert!(matches!(r2, Err(CapabilityError::Timeout { .. })), ...);

    let snap2 = typed.budget().snapshot();
    assert_eq!(snap2.calls_used, 0,
        "M3 INVARIANT VIOLATED: second Timeout must NOT debit the quota; calls_used = {}",
        snap2.calls_used);
}
```

**Why this really verifies the invariant:**

- ONE cap, ONE quota bucket. The previous test used TWO independent
  caps on independent quota buckets, so a regression where
  `invoke_op` debited the quota on timeout would let the slow cap's
  two timeouts pass (the budget blew first) and the fast cap's
  quota-deny path would say nothing about the slow cap's bucket.

- The assertion reads the SHARED `Arc<QuotaState>::calls_used` via
  `budget.snapshot()` after each Timeout. If a regression moved
  `self.budget.try_call()` before the handler call, `calls_used`
  would climb to 1 after the first Timeout and 2 after the second;
  the assertion would fail with a clear message.

**Verified by temporarily injecting the regression.** I moved
`try_call()` above `self.handler.invoke(input)` in
`src/kernel/cap/typed.rs::invoke_op`, ran the test, and confirmed it
fails with:

```
thread 'm3_invoke_op_timeout::timeout_does_not_debit_quota' panicked at
tests/capability/m3_invoke_op_timeout.rs:315:5:
assertion `left == right` failed: M3 INVARIANT VIOLATED:
  first Timeout must NOT debit the quota; calls_used = 1
  left: 1
 right: 0
```

The regression was reverted before commit; `cargo test` is back to
green. The companion `successful_handler_debits_quota` test was also
enhanced to assert `budget.snapshot().calls_used` after each call
(0 → 1 → 2 → 2), so a regression that double-debits or fails-to-debit
on success is caught directly on the same single cap.

## Fix 2 — Resource docstring

The previous Round 1 fix (P2-N, commit fe46532) acknowledged that
the trait returns `Result<Value, String>` but kept saying the dispatch
wraps the String error as `CapabilityError::KindMismatch`. In
production (`src/kernel/cap/typed.rs`):

- The CapKind check (sync vs stream) runs FIRST and produces
  `CapabilityError::KindMismatch { name, expected, got }` at lines
  200 and 250.
- The handler runs only if the kind check passes. Its `Err(String)`
  is wrapped as `CapabilityError::Handler { name, message }` at
  lines 244 and 311.

So the trait's default-implementation String error reaches the user
as `CapabilityError::Handler`, NOT `KindMismatch`. Fix 2 updates the
three docstring sites in `src/kernel/resource.rs` (file-top,
`invoke` method, `open` method) to spell this out and point readers
at the actual production call sites.

## Design trade-offs / blockers

1. **Pre-existing clippy errors on baseline.** The previous review-fix
   report (`ea4f8b7`) claimed `cargo clippy --all-targets
   --features loom-tests -- -D warnings` was clean, but the current
   toolchain (clippy 0.1.100 / rustc 1.100.0-nightly) flags two
   lints the previous environment didn't:

   - `tests/concurrency/d3_wall_clock_subtree_accumulates.rs:101`
     `clippy::int_plus_one` — `child_after >= child_before + 1` →
     `child_after > child_before`.
   - `tests/concurrency/d5_dead_quota_fields.rs:24`
     `clippy::needless_borrows_for_generic_args` —
     `serde_json::to_value(&q)` → `serde_json::to_value(q)`.

   These are mechanically trivial and have no behavioural effect. The
   task constraint "every commit ends with `cargo clippy --all-targets
   -- -D warnings` green" conflicts with the acceptance criterion
   "don't widen scope" — both are explicit constraints from the task
   description. **Decision** (asked supervisor, received approval):
   separate prep commit `phase5/fix/clippy-baseline-cleanup`
   (7452cf9) makes the baseline clippy-clean before the three
   review fixes. Each subsequent commit then runs against a green
   baseline.

2. **`MockClock` cannot drive the M3 timeout test.** The handler
   measures elapsed via `start.elapsed()` where `start = clock.now()`.
   `MockClock::pinned` returns the same `Instant` on every `now()`
   call, but `Instant::elapsed()` compares against the real
   `Instant::now()`. A pinned mock clock reports real elapsed time
   regardless of whether the handler slept. The replacement test
   therefore uses the default `SystemClock` (factory `new(space)`);
   the `MockClock` path is exercised by
   `tests/delta/quota_clock_eviction.rs` for quota-window sliding,
   which does not depend on handler elapsed time.

3. **Test name `timeout_does_not_debit_quota_then_success_debits`
   dropped.** It was misleading: the name promised "timeout-then-
   success" but the impl used two separate caps. The replacement
   splits the invariant into two single-cap tests:
   - `timeout_does_not_debit_quota` (new) — verifies the timeout
     path leaves `calls_used == 0`.
   - `successful_handler_debits_quota` (enhanced) — verifies the
     success path debits `calls_used` once per call.
   The "then" is implied by the test naming pattern (the first test
   covers the first half, the second test covers the second half);
   no test name carries the misleading combined claim.

4. **No new architecture, no new types, no Cargo.toml dependency
   version bumps.** The only non-docstring/non-Cargo.toml change is
   the prep commit (two `;`-bounded mechanical replacements in
   existing test files).
