## 1 — `phase6/feat/drop-consumes-field`

Breaking change: the legacy `[[consumes]]` manifest block is gone.

### Removed

- `PluginManifest.consumes: Vec<DependencyRef>` field
  (`src/host/manifest/types.rs`).
- `ManifestBuilder::consumes(...)` setter, the `consumes` field
  on the builder, and the `Default::default()` row in the doc table
  (`src/host/manifest/builder.rs`).
- `runtime::lifecycle::log_legacy_consumes` (the audit printer that
  walked `m.consumes`); phase 5 of the 8-phase orchestrator is now
  a no-op marker so the numbering stays stable
  (`src/runtime/lifecycle.rs`).
- `.consumes("echo", "^0.1", "echo")` call in
  `plugins/echo/chain/manifest.rs`; the chain plugin already
  declares its echo dependency via `.requires("echo", "echo")`
  so the resolver still binds it.
- `[[consumes]]` block in `plugins/test_only/broker/broker.toml`.
- `consumes: vec![]` initialiser from every `PluginManifest {...}`
  literal in `tests/{epsilon,zeta}/` (15 call sites across 6 files).
- `consumes: vec![]` initialiser from
  `host::resolver::tests::make_manifest`.

### Preserved (per literal task instruction)

- `DependencyRef` struct in `src/host/manifest/types.rs:127`.
  Per the task: *"保留 `DependencyRef` 类型（`requires` 也用）"*.
  Strictly speaking nothing imports it any more (the
  parenthetical justification is wrong — `requires` uses
  `CapabilityRequirement`), so this is one orphan public type.
  Following the literal task wording beats removing it under a
  silent new decision; flagged here for a future clean-up commit
  if desired.
- `removed_quota_field_warnings` in
  `src/host/manifest/load.rs`. The task references deleting
  `warn_on_removed_quota_fields` "这类" (this kind of code); the
  closest function is `removed_quota_field_warnings` which is
  tested by 4 tests in `tests/concurrency/d5_dead_quota_fields.rs`.
  Deleting it would break those tests (which would violate the
  *"不修改 tests 绕过问题"* rule). The function is unrelated to
  `consumes` and out of scope for this breaking change; left
  intact. CHANGELOG entry also stays silent on quota warnings.

## 2 — `phase6/refactor/lifecycle-split`

`src/runtime/lifecycle.rs` (255 LOC) becomes a four-file
`lifecycle/` directory. `git rm` removed the monolith.

### Final structure

| File             | LOC | Responsibility                                |
|------------------|-----|-----------------------------------------------|
| `mod.rs`         | 182 | `run()` + phase glue + `orchestrator_tests`   |
| `phases.rs`      | 14  | 8-phase docstring table                       |
| `manifests.rs`   | 86  | `load_manifests` + 2 unit tests               |
| `print.rs`       | 140 | `print_manifests` + 3 unit tests              |
| `shutdown.rs`    | 28  | `spawn_http_bridge` (HTTP bridge + Ctrl-C)    |
| **total**        | 450 | (was 255 in the monolith; +195 = tests + docs) |

### Notable changes inside the split

- `load_manifests` drops the dead `_dir: &str` parameter; the
  loader never read the filesystem and the parameter was a
  positional no-op.
- `serve(addr, cspace, ctrl_c_future)` is moved verbatim from
  `run()` into `shutdown::spawn_http_bridge(addr, cspace)`,
  returning the `JoinHandle<()>`. Behaviour unchanged.
- `phases.rs` is a docstring-only file (no executable code); the
  module exists so the phase map is one canonical reference.

### README

Updated to point phase 7 at `runtime::lifecycle::shutdown` and to
reflect the new `lifecycle/` directory layout in the `Layout`
section.

## 3 — `phase6/test/lifecycle-orchestrator-tests`

Four new tests in `runtime::lifecycle::orchestrator_tests` cover
the deterministic, host-side phases of the 8-phase orchestrator.

| Test                                                | Phase | What it asserts                                       |
|-----------------------------------------------------|-------|-------------------------------------------------------|
| `phase1_load_manifests_returns_eleven_sorted`       | 1     | Loads exactly 11 manifests, sorted by `plugin.name`.  |
| `phase1_load_manifests_no_consumes_field`           | 1     | Each manifest exposes `plugin/requires/host/...` but the `consumes` field is gone (compile-time gate). |
| `phase3_resolve_succeeds_on_loaded_manifests`       | 3     | Loaded manifests resolve cleanly; `mint_order.len() == manifests.len()`. |
| `phase8_shutdown_events_publish_in_order_on_empty_cspace` | 8 | `ShutdownStarted` and `ShutdownCompleted{..}` both reach the event bus on an empty cspace. |

Phase 7 (HTTP bridge + wait) is intentionally not exercised; it
needs a real socket and a tokio runtime and is the integration
test layer's responsibility.

## Deviations from the literal task

1. **`DependencyRef` is kept** (per *"保留 `DependencyRef` 类型"*),
   even though nothing references it any more. Strict
   zero-tech-debt reading would remove it, but the task
   instruction is explicit and the orphan is harmless (one
   public type, no warnings). Recommend a follow-up commit if
   the team wants it gone.

2. **`removed_quota_field_warnings` is kept** (the task reference
   to *"warn_on_removed_quota_fields 这类"* is ambiguous: no such
   function exists; the closest is `removed_quota_field_warnings`
   which has 4 dedicated tests in
   `tests/concurrency/d5_dead_quota_fields.rs`). Deleting it
   would break those tests, violating the
   *"不修改 tests 绕过问题"* rule.

3. **`lifecycle/mod.rs` ended at 182 LOC** (vs the
   ~80 LOC the task hinted at) because the
   `orchestrator_tests` module lives inside the same file
   (commit 3 appended +104 LOC of tests). The runtime glue itself
   is ~78 LOC, matching the target.
