```markdown
  `pub struct DependencyRef { plugin, version, capability }`

  removed in Phase 5). The loader no longer scans the

  serde's default `deny_unknown_fields = false` already
  ignores the dead keys silently, so the diagnostic was
  redundant. The four `d5_warning_capture_*` tests that
  exercised the warning builder directly are deleted;
  the schema-level guards
  (`quota_spec_has_no_token_or_byte_fields`,
  `manifest_with_dead_quota_fields_still_loads`)
  remain.
```

## Design decisions and notes

- **Both commits on the same branch.** The task named the two
  commits but did not require separate branches; sequential commits
  on `phase5/refactor/kernel-host-runtime-split` keep the Phase 7
  history linear and each commit independently revertable.
- **No `git grep` surprises in non-obvious places.** The
  `DependencyRef` references were exactly the three locations named
  in the task (definition + 2 re-exports). The
  `removed_quota_field_warnings` references were exactly the
  definition + the call inside `from_toml_str` + the four D5 tests
  + one docstring line referencing the symbol by name.
- **No live production code path depends on the removed warning
  diagnostic.** Searched `src/` and `tests/` for
  `tokens_per_minute` / `bytes_per_minute` references: the only
  remaining hits are in `src/kernel/quota/{spec,state}.rs` and
  `src/kernel/space/graph.rs` as historical Phase 5 D5 fix notes, and
  the two kept D5 tests (TOML fixture + assertions on the missing
  keys). No other loader, validator, or runtime path inspected
  these strings, so deletion is safe.
- **`PluginManifest::from_toml_str` / `from_path` re-exports
  preserved.** Those are part of the public `PluginManifest` API
  (not the orphan); the task did not call them out and they are
  used by integration tests under `tests/common/mod.rs` and
  `tests/gamma/`.
- **Clippy baseline note.** The pre-existing
  `warning: unused dependency 'loom'` line emitted by
  `cargo clippy --all-targets --features loom-tests -- -D warnings`
  is unchanged: it is a Cargo.toml manifest lint, not blocking
  (`-D warnings` exit code is 0), and the task forbids touching
  Cargo.toml. No new clippy warnings introduced.
- **`cargo doc --no-deps` clean.** The module-level docstring on
  `src/host/manifest/load.rs` was rewritten to no longer mention
  the removed fields as the load's behaviour; intra-doc links to
  [`PluginManifest`] still resolve.
- **No new architecture, no deprecation aliases, no TODO/FIXME
  introduced.** The deletion is purely subtractive.
