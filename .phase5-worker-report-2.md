### Phase 2 — `phase5/refactor/kernel-pure-split` (18be468)

Submodule layout (`src/kernel/`):
- `ids`, `kind`, `rights`, `meta`, `chunk`, `clock`,
  `error`, `resource`, `slot` (top-level modules).
- `cap/` (typed `Capability<R>` + erased `AnyCapability`).
- `quota/` (spec + state + budget).
- `space/` (`CapabilitySpace` + `derivation` + `revocation`
  + `graph` + `events` + `namespace`).

Defect fixes (all 15):
- **D2** — `kernel/space/mod.rs::install_derived` checks
  `slots.contains_key(&parent)` before allocating the new
  slot id; returns `CapabilityError::SlotEmpty(parent)` on
  miss. Closes Interleaving 2.
- **M1** — `kernel/space/mod.rs::install` takes
  `parents.write()` as a no-op lock first, matching the
  canonical `parents → slots → names` order.
- **D3** — `kernel/quota/state.rs::CapabilityBudget::share_with`
  clones the parent's `Arc<AtomicU64>` and
  `Arc<QuotaState>` rather than allocating fresh. Derived
  caps now report subtree-wide wall-clock usage.
- **D1** — `kernel/cap/typed.rs::derive` doc compressed to
  the precondition line + `debug_assert!` tripwire.
- **M2** — `kernel/cap/erased.rs::AnyCapability::mark_revoked_dyn`
  default impl panics; every `AnyCapability` impl MUST
  override.
- **M3** — `kernel/cap/typed.rs::invoke` + `invoke_op`
  reorder: handler runs first, wall-clock recorded, then
  timeout check, then quota debit. Added
  `CapabilityError::Timeout` variant for the late-timeout
  case.
- **M4** — `kernel/cap/typed.rs` + `slot.rs` +
  `erased.rs` all return typed `CapabilityError`. Pipeline
  consumes the typed error via `invoke_dyn` (Display
  conversion).
- **n1** — `kernel/slot.rs` three
  `"slot X empty or revoked"` format! strings replaced with
  `CapabilityError::SlotEmpty(id).to_string()`.
- **n3** — `kernel/quota/state.rs` `quota_state` field is
  private; public surface is `snapshot()` +
  `pub(crate) try_call()`.
- **R1** — `kernel/space/namespace.rs` is the single home
  for `namespace_prefix_matches`. The old
  `capability::graph::namespace_starts_with` is gone.
- **R4/R5/R6/R7** — `kernel/space/revocation.rs::revoke`
  takes a `RevokeMode::{Single, Tree}` selector;
  `revoke_with_sweep` is gone. `grant`/`transfer`/`restrict`
  share the same `derive_with` body in `derivation.rs`.
- **m3** — `kernel/slot.rs::Slot::kind()` removed.

`CapabilityError` also gained a `SlotEmpty` / `Revoked`
split (M4), plus `PartialEq + Eq + Clone` for the
pattern-matching tests.

Back-compat shims:

### Phase 3 — `phase5/refactor/host-composition` (1f887cd)

Submodule layout (`src/host/resolver/`):
- `error.rs` — typed `ResolveError` variants.
- `index.rs` — contract-name → `ContractEntry` index,
  dedup + ambiguity detection.
- `topo.rs` — Kahn's algorithm with cycle detection.
- `plan.rs` — `ResolvedPlan` + `ResolvedBinding` +
  `Reachable`. `Reachable` migrates here from
  `host/reachable.rs` (now a back-compat shim).

The resolver is now a thin orchestrator: `index → topo →
plan`, each phase independently testable.

`host/pipeline.rs` consumes typed `CapabilityError` (M4).
`PipelineError::SlotRevoked` fires when `invoke_dyn`
returns a message containing `"capability revoked"` or
`(lowercased) "slot" + "empty"`.

emits a stderr warning when the deleted quota fields
appear in source.

`src/boot/` deleted entirely. `src/runtime/` created:

├── lifecycle.rs      7-phase orchestrator (thin)
├── activate.rs       activator_for + per-arm const asserts
├── teardown.rs       ruin_runtime_plugins

    ├── generator.rs  mint_generator
    └── agent.rs      mint_agent

`http_bridge.rs::router` and `serve` lost their unused
`cordis::Context` parameter (m6). The HTTP bridge talks to
the cspace directly.

`activate.rs::dispatch_consistency` replaced with a series
of `const _: () = assert!(eq(NAME, NAME));` lines per
runtime-plugin name. Rust's const eval cannot `match` on
`&str` yet (str::PartialEq is not stable in const), so the
per-arm check uses a byte-level equality helper; the
runtime `activator_for` itself stays dynamic because
`Arc<dyn Plugin>` isn't const-callable.

## Design trade-offs encountered

1. **`CapabilityError::SlotEmpty` vs `Revoked` split** —
   the M4 spec lists `Revoked`/`Empty` as separate
   variants; the Phase 1 tests assert
   `err.contains("capability revoked")`. We split
   `SlotEmpty` (slot was never installed / was empty) from
   `Revoked` (slot was installed then revoked) and gave
   `Revoked` a display message that contains the
   substring.

2. **`D2` check target (`slots` vs `parents`)** — the
   original WIP commit checked `parents.contains_key(&parent)`,
   which wrongly rejected every root cap (roots are never
   in `parents`). We moved the check to
   `slots.contains_key(&parent)` so it correctly
   distinguishes "parent slot exists" from "child slot has
   a parent pointer".

3. **`Capability::bind_slot` for revoked-cap errors** —
   the typed `CapabilityError::Revoked(SlotId)` requires
   a real `SlotId`. We added a `slot: Option<SlotId>` field
   to `Capability<R>`, populated by `install` /
   `install_derived`. Without this, the SlotId would
   panic on `NonZeroU64::new(0)`.

4. **`dispatch_consistency` const-assert pattern** —
   Rust's `const fn` cannot `match` on `&str` yet, so the
   per-arm `const _: () = assert!(is_known(NAME))` pattern
   uses a byte-level equality helper. The runtime
   `activator_for` itself stays dynamic because
   `Arc<dyn Plugin>` isn't const-callable. The const
   assertions verify the literal name in
   `RUNTIME_PLUGINS` matches the literal name in the
   activator dispatch — a typo in either is a build error.

5. **`CapabilityError::contains` shim** — Phase 1 tests
   call `err.contains("capability revoked")` directly on
   the error value. We added `CapabilityError::contains(&str)`
   as a thin wrapper around `self.to_string().contains(pat)`
   to keep those tests compiling without forcing them
   through `to_string()`.

6. **`CapabilityError` derives** — the integration tests
   pattern-match on `CapabilityError::SlotEmpty(_)` and
   compare `Result<Value, CapabilityError>` values with
   `assert_eq!`. We derived `PartialEq + Eq + Clone` on
   `CapabilityError`. `SlotId` already derives all the
   needed traits; the `OperationRights` / `QuotaKind`
   dependencies derive them too.

7. **Back-compat re-exports over test edits** — the task
   says "不修改 tests 绕过问题". The Phase 1 integration
   tests use pre-Phase-5 paths
   (`odyssey::capability::*`, `odyssey::kernel::factory::*`,
   `odyssey::kernel::manifest::*`, etc.). We chose to add
   back-compat re-exports in `lib.rs` and `kernel/mod.rs`
   rather than rewrite 30+ test files.

8. **`ResolvedBinding` shape** — Phase 1 tests build
   `ResolvedBinding` literals with 4 fields (`handle`,
   `provider`, `capability`, `contract`). The WIP commit
   had 6 fields including `requirement: CapabilityRequirement`
   and `provider_slot: SlotId`. We dropped the extra two to
   match the tests' literal-field shape.

9. **`ResolveError` variants** — Phase 1 tests pattern-match
   `Unprovided { contract, by: String }`,
   `Ambiguous { contract, a: String, b: String }`,
   `Cycle { chain: Vec<String> }`. We changed the variants
   from carrying `PluginId` / `Vec<PluginId>` to
   `String` / `Vec<String>` (the string is
   `"name@version"` or just `"name"`).

10. **Resolver unit test** — the WIP commit's `unprovided_contract_errors`
    test asserted against `DuplicateName | Ambiguous`
    which never fires for a single manifest with no
    requires. We replaced the test with the actual
    unprovided-contract scenario so the assertion matches
    the implementation.

11. **`QuotaSpec::with_calls_per_minute` is missing in
    integration tests** — the `tests/delta/quota_basic.rs`
    tests call `QuotaSpec::unlimited().with_calls_per_minute(2)`,
    which required the `with_calls_per_minute` builder on
    `QuotaSpec`. We kept that builder.

12. **`graph::CapabilityGraph::from(&space)`** — the
    WIP commit had `CapabilityGraph::snapshot(space)`
    (static method). The tests call `from(&space)`. We
    added the `From<&CapabilitySpace>` impl and renamed
    `CapabilityGraph::capabilities` → `nodes` so
    `graph.nodes.len()` works (also a test assertion).

13. **`space.children_of(slot)`** — the `p6_graph` test
    asserts `space.children_of(root) == vec![a]`. We added
    the method to `CapabilitySpace`.

## Open risks / follow-ups

1. **`tracing::warn!` would have been cleaner** — the
   loader warning uses `eprintln!` because `tracing` isn't
   a dependency. If a later phase wants structured logging,
   add `tracing` to `Cargo.toml` and convert.

2. **`PipelineError::SlotRevoked` still uses substring
   matching** — `host/pipeline.rs::SyncStage::run` checks
   `lowered.contains("slot") && lowered.contains("empty")`
   to decide if an `invoke_dyn` error is a slot-revoked
   case. A typed-error variant on `PipelineError` would be
   cleaner; the substring path is the M4 transition.

3. **`SlotId::new(1)` sentinel in graph namespace tree**
   — `kernel/space/graph.rs::build_namespace_tree` uses
   `SlotId::new(1)` as a placeholder for nodes inside
   `NamespaceNode::capabilities`. The HTTP bridge should
   re-join with the flat `nodes` list when rendering.

4. **`quota_state` Arc clone on `share_with`** — D3 fix
   shares the `Arc<QuotaState>`, which is correct for
   subtree accounting but means the per-minute call window
   is global across the subtree, not per-cap. That matches
   the original seL4 design but is a subtle operator-visible
   behaviour change.

5. **`Slot::kind()` removed in m3** — if a downstream
   plugin uses `slot.kind()`, the removal is a breaking
   change. No plugin in `src/plugins/` uses it.

6. **Out-of-scope defect backlog** — D4, R2-R3, R8-R11,
   n4 remain for Phase 6 / 7 / 9 workers.
